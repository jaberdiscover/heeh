Four ideas, one operating model

The game begins with a common language. Each round then asks the audience to use these concepts to make a real service-management decision.

SLI

What we measure

A service signal such as availability, latency, successful requests, or error rate.

SLO

Our reliability target

The internal objective that defines the expected level of service performance.

SLA

Our external commitment

The formal service commitment and potential consequence when the agreed level is missed.

EB

Our decision margin

The acceptable amount of unreliability available before the SLO is no longer achieved.

→
Operating principle for the simulation Do not wait for an SLA breach. Use the SLI trend, SLO position, burn rate, and remaining error budget to decide whether to release, investigate, or stabilize.
Suggested talk track: “We already know the definitions. The question now is how these concepts change an actual engineering decision. In each round, the dashboard becomes less healthy and the audience must decide how the SRE team should respond.”

How to run the game

Begin with the one-minute concept bridge. Then present each dashboard and read the scenario aloud. Ask the audience to vote on A, B, or C. Select the majority choice, reveal the consequence, and connect the learning point back to the SRE theory.
